Session overview & outcomes

Gens Invaders is a Space Invaders–style game for the Sega Genesis built with SGDK, based on the ohsat tutorial. The project had drifted out of sync with a newer SGDK and had several latent bugs. Over four turns the game was analyzed, repaired, and made to build cleanly again.

2 Fix powerup toggle & missing shootBullet

User“fix the powerup toggle and the missing shootbullet, but please document what you did, I want to learn about it since this is a hobby project of mine to learn the SGDK toolkit.”

Change A — forward declaration

 int offset = 0;
+/* Function prototypes — shootBullet() is called by positionEnemies() before
+   it is defined; modern SGDK GCC treats implicit declarations as errors. */
+void shootBullet(GameEntity shooter);
 /* Auxiliary functions for game processing */

Change B — activatePowerup()

-        maxPlayerBullets = MAX_PLAYER_BULLETS;   // == default, did nothing
+        maxPlayerBullets = MAX_BULLETS;          // actually raise the cap (6)
         powerupTimer = POWERUP_DURATION;
-        PAL_setPaletteColors(18, RGB24_TO_VDPCOLOR(0xf83000), DMA);
+        PAL_setColor(34, RGB24_TO_VDPCOLOR(0xf83000));
         powerOn = POWER_ON;

Change C — deactivatePowerup()

-    PAL_setPaletteColors(34, RGB24_TO_VDPCOLOR(0x0078f8), DMA);
+    PAL_setColor(34, RGB24_TO_VDPCOLOR(0x0078f8));
+    powerOn = POWER_OFF;   // <-- the actual toggle fix (was missing)

Why these matter (the learning notes)

  • Prototype: C compiles top-to-bottom; calling a function the compiler hasn’t seen triggers an implicit-declaration error on SGDK’s newer GCC.
  • Toggle: the A-button does if (powerOn) deactivate(); else activate(); — without resetting powerOn it stuck at 1 after the first press.
  • RapidFire: setting the cap to the default value (3) meant the powerup did nothing; MAX_BULLETS (6) makes it real.
  • Palette API: PAL_setPaletteColors expects a u16* array; passing a single color value triggered an int → pointer warning and the runtime crash you’d marked “aquí truena”. PAL_setColor(index, value) is the correct single-entry call (matches main.c:355).

4 Powerup auto-expire & the sound issue

Part 1 — auto-expire

// new function, after deactivatePowerup()
+void updatePowerup() {
+    if (powerOn) {
+        if (powerupTimer > 0) {   // guard: u16 underflow would wrap to 65535
+            powerupTimer--;
+        }
+        if (powerupTimer == 0) {
+            deactivatePowerup();
+        }
+    }
+}
 ...
         positionEnemies();
         handleCollitions();
+        updatePowerup();    // tick RapidFire down so it auto-expires
         SPR_update();

Learning note: powerupTimer is unsigned (u16) — decrementing 0 wraps to 65535, so the > 0 guard prevents the powerup getting stuck on for ~18 minutes. Lasts ~1.6 s at 100 frames (NTSC); raise POWERUP_DURATION to extend.

Data-driven difficulty table (difficultyTable): EASY (no descent, 1 enemy bullet), NORMAL (8 px step, up to 2 bullets, two distinct enemies fire together), HARD (16 px step, two fire together, up to 4 bullets on screen). Enemy bullets now have their own pool (enemyBullets[MAX_ENEMY_BULLETS]). 12/11/2026 (with Bimo) - Difficulty retune

Root cause. HARD used the correct table row (currentDiff was not overwritten and the HUD showed HARD), but fire still used the shared SHOT_INTERVAL of 120 frames and the same 1 px horizontal speed as NORMAL. The 4-bullet cap almost never filled: at speed 5 a bullet leaves the screen in about 38 frames, long before the next volley. The 16 px step only happens on an edge bounce, at the same bounce rate as NORMAL. No sign of frame drops (light sprite load, small loops, vblank wait).

The table now also has shotInterval, enemySpeed and bulletSpeed. EASY fires every 90 frames (chance 10, 1 bullet). NORMAL is unchanged. HARD uses interval 60, step 16, horizontal speed 2 and bullet speed 6.

12/11/2026 (with Bimo) - Title screen

Replaced the standalone SELECT DIFFICULTY menu with a title screen (STATE_TITLE). The logo is a two-row blocky GENS / INVADERS wordmark made of solid 8x8 tiles on plane A (5x5 glyphs for GENS, 4x5 for INVADERS) plus a drop shadow, with a gold/orange color pulse. Tiles were used instead of sprites so INVADERS can sit on one scanline without hitting the 20-sprites-per-line limit. The version V0.1.xx is shown under the logo. Game sprites are hidden; the starfield keeps scrolling on plane B.

Menu: START GAME (INICIAR) and DIFFICULTY: EASY/NORMAL/HARD. UP/DOWN move the cursor; LEFT/RIGHT (and START or A on DIFFICULTY) cycle the level; START on START GAME begins the match. After GAME OVER / YOU WIN, START returns here with the last difficulty preselected.

12/11/2026 (with Bimo) - Second enemy row

Two rows of 7 enemies (14 total) move, bounce and step down as one formation. GAME OVER uses the lowest living enemy; YOU WIN when both rows are cleared. Firing prefers the bottom-most living ship in each column. Difficulty table unchanged.

Per-row EnemyRowType (sprite, palette, points). Both rows currently reuse ship; the bottom row is tinted on PAL3 (10 points) and the top row keeps PAL2 (20 points).

Sprite budget. Software sprites: 14 enemies + 1 player + 6 player bullets + 4 enemy bullets = 25. Hardware sprites (16x16 = 4 cells, 8x8 = 1): 56 + 4 + 6 + 4 = 70 of 80. Per scanline, a full row uses 14 of 20; rows are spaced 24 px so they do not share a line. A later unique 16x16 graphic per row has no extra performance cost beyond the same sprite budget.

12/11/2026 (with Bimo) - Opposite rows on HARD

New rowsOpposite flag in DifficultyConfig: EASY=0, NORMAL=0, HARD=1. Set NORMAL to 1 to enable the same behavior there. EASY and NORMAL keep the single-formation movement.

On HARD the top row starts right and the bottom row starts left (shifted to the right so it is not already on the left edge). Each row bounces using only its own living enemies, and only the bouncing row steps down (using stepDown and enemySpeed from the table). A row will not descend if it would come within 24 px (ENEMY_ROW_SPACING) of the next living row below; it just reverses. If the bottom row is cleared, the top row can drop freely. GAME OVER still uses the lowest living enemy.

12/11/2026 (with Bimo) - Opposite rows on NORMAL too

NORMAL now also has rowsOpposite=1. Its other values stay the same (step 8, speed 1, interval 120, cap 2). EASY stays 0 (both rows move together). HARD is unchanged.

12/11/2026 (with Bimo) - NORMAL always fires its volley

After the modular refactor Alberto reported that enemy ships on NORMAL barely seemed to shoot. A comparison with V0.1.25 (37ba68e) found no regression: the volley ticker, bullet pool, difficulty getters and table values were unchanged. NORMAL still had fireChance 8, so about one in five volleys was skipped; two misses in a row left 4–6 seconds with no enemy bullets. EASY and HARD already fire on every attempt.

fireChance on NORMAL is now 10. Every 120-frame volley (~2 s) fires two shots, still capped at 2. Interval, speed, step, cap and rowsOpposite are unchanged. EASY and HARD are unchanged.

12/11/2026 (with Bimo) - More varied enemy shooters

On NORMAL the cadence was correct (two ships every ~2 s) but the same ships kept firing. Three causes: SGDK only auto-seeds random() on the first button of the session (often a title-menu tap just after boot, with a similar getTick()); random() % n used the low bits of the 16-bit xorshift and could clump columns; and the picker did not avoid the columns from the previous volley.

Pressing START to begin a match now calls setRandomSeed with a title-screen frame counter, vtimer and getTick(). Each volley still uses the bottom-most living enemy in a column, but the columns are chosen at random, stay distinct within the volley, and skip the previous volley’s columns when other eligible ones exist. Picks use the high bits of random(). Applies to all difficulties; the difficulty table is unchanged.

12/11/2026 (with Bimo) - Player explosion

When the player is hit, the ship is hidden and a 6-frame 16×16 explosion plays at that position for 48 frames (~0.8 s, 8 ticks per visual frame): white flash, expanding orange/red fireball, debris and fade. The sheet is res/tiles/imgexplosion.bmp (96×16, indexed, color 0 transparent, same PAL1 as space.bmp), added as SPRITE explosion with FAST and anim speed 0 so frames are advanced by hand and do not loop.

Input stays blocked (health is already 0) and pause is disabled during the explosion. Enemy fire and the shot ticker are skipped via player_isExploding(); ships and bullets already on screen keep moving. A short decaying horizontal shake on the starfield (BG_B) and a 4-frame flash of PAL1 color 2 to white are cheap extras.

If lives remain, the rest of RESPAWN_DELAY (42 frames) runs after the explosion so total dead time stays ~90 frames, then the usual blinking invulnerability. If no lives are left, GAME OVER waits until the explosion finishes (player_update returns 1). Logic lives in the player module. Hardware-sprite budget stays at 70: the 16×16 explosion (4 cells) replaces the hidden ship.

12/11/2026 (with Bimo) - Shield power-up

Button C activates a shield (B was already shoot, A is still RapidFire). It starts charged at the beginning of a match, lasts 5 s, then recharges for 30 s. NTSC uses 300 / 1800 frames; on PAL, IS_PAL_SYSTEM selects 250 / 1500 so the wall-clock time stays the same. The project had no PAL timing before.

While it is on, a 32×32 4-frame pulsing blue/white bubble (res/tiles/imgshield.bmp, same PAL1, color 0 transparent) follows the ship. Enemy bullets that touch the 32×32 box are destroyed and do no damage. There is no ship-vs-enemy body collision in this game, so the shield only has to stop bullets. Short PCM blips play on channel 1 when the shield goes up and when recharge finishes.

It cannot be used during the player explosion, while dead, while paused, or during recharge. The timer only ticks in STATE_PLAYING, so pause freezes it. On life loss the recharge (or LISTO) state is kept; a bullet cannot kill the player while the shield is up. A new match calls powerups_reset and starts ready. The HUD shows ESC: LISTO, ESC: ON n or ESC: ns on the right of line 2, redrawn with the score line so the existing layout stays intact. One extra hardware sprite (32×32 = 1 VDP sprite).

12/11/2026 (with Bimo) - Shield times by difficulty

After playtesting, 5 s of shield felt too long. Duration and recharge now live in the difficulty table (shieldDurationSec / shieldRechargeSec): EASY 5 s / 10 s, NORMAL 3 s / 20 s, HARD 2 s / 30 s.

powerups still converts those seconds to frames with IS_PAL_SYSTEM (×60 NTSC, ×50 PAL) at reset, so the wall-clock time stays the same on both systems. The HUD continues to show remaining seconds (ESC: ON n, ESC: ns). The fixed SHIELD_DURATION_* / SHIELD_RECHARGE_* macros were removed from config.h.

12/11/2026 (with Bimo) - Shield HUD bar

The numeric shield HUD (ESC: LISTO / ESC: ON n / ESC: ns) is now a short ESC label and an 8-tile bar (64 levels, eighth-block tiles) on the right of line 2. SCORE and DIFF are unchanged.

While the shield is up the bar is blue (PAL1) and drains with the time left. During recharge it fills in dark red (PAL1). When it is ready it is full and green (PAL3 color 1, the same green as the bottom enemy row) and flashes blue for about half a second when the recharge finishes, along with the existing ready SFX.

Plane A is only rewritten when the level, state or blink phase changes. The tiles are generated in code and loaded at TILE_USER_INDEX + 2 (the title still uses the first two user tiles). No new palette or BMP; fill colors already exist in PAL1 / PAL3. The empty part of the bar is a black track (palette index 4).

12/11/2026 (with Bimo) - Invasion GAME OVER on body contact

The match no longer ends just because a living enemy reaches the player's row (PLAYER_START_Y) without touching the ship. collision now tests enemy-player body overlap: that is always GAME OVER after the player's explosion (player_hitFatal), even if lives remain. Classic invasion: you do not just lose one ship.

The shield and post-respawn invulnerability do not protect against that contact (they still stop enemy bullets).

If a ship steps past the player's height without overlapping in X, the formation keeps marching. When any living enemy reaches the visible bottom (y + h >= BOTTOM_EDGE, 224), the same fatal explosion and GAME OVER apply, so the game cannot stall with invaders sitting below the gun. They do not bounce or freeze.

12/11/2026 (with Bimo) - Enemy explosions

Every destroyed enemy now plays a burst that is distinct from the player's death explosion: a new 6-frame 16x16 sheet (res/tiles/imgenemyexp.bmp, same palette as space.bmp) with a compact white/yellow flash and green sparks that fly outward. It is drawn with PAL3 (green/yellow/white in play) for 24 frames (~0.4 s at 60 Hz), smaller and faster than the player's 48-frame orange/red fireball.

The ship disappears immediately and the burst occupies its place. Explosions are independent sprites: they do not take part in collisions or formation movement. A pool of 6 (MAX_ENEMY_EXPLOSIONS) can play at once; if it is full, the oldest slot is reused. Each burst is 1 VDP sprite (16x16). Peak hardware count is about 33 of 80; on a scanline the dead ships are already hidden, so bursts do not stack on a full live row and stay under the 20-sprite limit.

On a body crash into the player (or a landing at BOTTOM_EDGE), the enemy uses this new animation and the player uses theirs, then GAME OVER as before. If several enemies overlap the player in the same frame, all of them explode. A short, higher-pitched pop (res/sounds/enemyexp.wav, PCM id 69) plays on channel 3 so it can sit next to the player's explosion on channel 2.

13/11/2026 (with Bimo) - Endless waves and version 0.3

Clearing both rows no longer ends the match with YOU WIN. A centered OLEADA N banner plays for about 1.5 s (90 NTSC frames / 75 PAL), then two new rows spawn at the top. Score, lives and the shield / RapidFire state are kept. Enemy bullets are cleared; player shots and any explosions already playing continue.

Wave 1 uses the existing difficulty table as-is. Later waves scale a runtime copy: shorter volley interval, higher horizontal speed, more shots per volley (capped at the 4-bullet enemy pool), a modest bump to bullet speed, and on NORMAL / HARD a modest increase in step-down. EASY never starts descending and stays at a 2-bullet cap. Opposite-row movement and the random column picker are unchanged.

13/11/2026 (with Bimo) - TOP 5 high-score table

A single table of 5 scores is saved in cartridge SRAM (magic GIHS, format 1, checksum). Each row stores 3 initials, the score, the wave reached and a difficulty letter (F/N/D). One shared table with a difficulty column was preferred over three separate lists. Invalid SRAM is replaced with defaults (GEN 1000, INV 800, UDL 600, AMH 400, BIM 200).

After GAME OVER, a score that beats 5th place (ties stay out) asks for arcade initials: up/down change the letter (A-Z, space, period), left/right move the cursor, A or START confirm. The table is then shown under GAME OVER with a blinking > on the new row. Otherwise the table is shown immediately. START still returns to the title.

The title menu has a third option, PUNTAJES (TOP 5). In BlastEm the save file is %LOCALAPPDATA%\blastem\rom\save.sram. Deleting it restores the defaults.

13/11/2026 (with Bimo) - Extra life every 1000 points

A ship is awarded at 1000, 2000, 3000... points (EXTRA_LIFE_SCORE in config.h, the same on every difficulty). Crossing several thresholds in one score jump grants all of them. Lives cap at 9 (LIVES_CAP) so SHIPS: n stays one digit; past the cap no ship is added but the next threshold still advances. Starting lives remain 3. The counter resets at the start of a match.

On a grant, the HUD updates immediately and a blinking +1 NAVE (or +n NAVE) appears for about 1 s on row 2. A short two-note ding (res/sounds/oneup.wav, PCM id 70) plays on channel 4. There is no award on GAME OVER or the initials entry. A 1UP during the last ship's bullet-death explosion cancels that GAME OVER; an invasion fatal hit still ends the match.

13/11/2026 (with Bimo) - Points per ship by difficulty

The only score source is still destroying an enemy with a player bullet (no wave bonus; invasion crashes award nothing). Previously the top row was worth 20 and the bottom row 10 on every difficulty, so a full wave was always 210 points.

Each ship now uses enemyPoints from the difficulty table: EASY 10, NORMAL 20, HARD 30, the same for both rows. A cleared wave is worth 140 / 280 / 420. Extra lives stay every 1000 points, so the first 1UP arrives around wave 8 on EASY, wave 4 on NORMAL and wave 3 on HARD.

The shared TOP 5 table and its placeholder entries are unchanged. Hard scores will climb faster; the F/N/D letter still shows the difficulty of each run.
